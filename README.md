Для работы с друзьями нужно несколько простых правил.

## 1. Всем дать доступ
GitHub → репозиторий → **Settings → Collaborators → Add people**. Без этого друзья не смогут пушить в твой репозиторий, только присылать форки.

## 2. Каждый работает в своей ветке
Это главное, что избавляет от «rejected / fetch first». Не пушьте все в `main`.

```bash
git checkout main
git pull                      # взять свежее
git checkout -b feature/leaderboard   # своя ветка под задачу
# ...работа, коммиты...
git push -u origin feature/leaderboard
```

Дальше на GitHub открываете **Pull Request** в `main`. Кто-то из вас смотрит изменения и нажимает Merge. Так `main` всегда рабочий.

## 3. Ежедневный цикл
```bash
git pull                  # перед началом работы
# работа
git add <файлы>           # не `git add .` вслепую
git commit -m "что сделал"
git pull                  # перед пушем, подтянуть чужое
git push
```

## 4. Если пуш отклонён (как у тебя было)
Значит, кто-то успел запушить раньше. Нужно подтянуть его изменения:

```bash
git pull --no-rebase      # слить чужое с твоим
# при конфликте: откройте файл, оставьте нужное, удалите <<<<<<< ======= >>>>>>>
git add <файл>
git commit
git push
```

`--force` и `--force-with-lease` не используйте, они затирают чужие коммиты. Строка про это в твоём `docs.txt` для командной работы не подходит.

## 5. Как не мешать друг другу
- **Договоритесь, кто какие файлы трогает.** Например, друг только CSS и шаблоны, ты `views.py`. Тогда конфликтов почти не будет.
- **Коммиты маленькие и часто.** Лучше пять мелких, чем один огромный.
- **Не коммитьте `db.sqlite3` и `.pyc`.** Теперь они в `.gitignore`. У каждого своя база, после `pull` достаточно `python manage.py migrate`.
- **Миграции коммитьте.** Если вы оба меняете модели, будут конфликтующие миграции с одним номером, поэтому о моделях договаривайтесь заранее.
- **Секреты и пароли не пишите в файлы репозитория.**

## 6. Защита `main` (по желанию)
Settings → Branches → Add rule для `main` → «Require a pull request before merging». Тогда в `main` нельзя запушить напрямую.

Если хочешь, могу показать на твоём проекте, как создать ветку и открыть Pull Request, например для таблицы лидеров.
